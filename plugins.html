1. Build and load the example

Requirements: macOS 15.6 or newer, Xcode / a Swift 6 toolchain, and a source checkout of Linvell. The example is in Examples/HelloPlugin. Run the following from the repository root in Bash. Build output and caches stay under ~/dev/build.

bash script/build_and_run.sh --build-only
open "$HOME/dev/build/linvell/debug/Linvell.app"

PLUGIN_BUILD="$HOME/dev/build/linvell/hello-plugin"
mkdir -p "$PLUGIN_BUILD"/{package,tmp,cache,config,security}
export TMPDIR="$PLUGIN_BUILD/tmp"
export CLANG_MODULE_CACHE_PATH="$PLUGIN_BUILD/cache/clang"
export SWIFTPM_MODULECACHE_OVERRIDE="$PLUGIN_BUILD/cache/swift"
PLUGIN_ARGS=(--package-path Examples/HelloPlugin
  --scratch-path "$PLUGIN_BUILD/swiftpm"
  --cache-path "$PLUGIN_BUILD/cache"
  --config-path "$PLUGIN_BUILD/config"
  --security-path "$PLUGIN_BUILD/security")
swift build "${PLUGIN_ARGS[@]}" --product HelloPlugin
PLUGIN_BIN="$(swift build "${PLUGIN_ARGS[@]}" --show-bin-path)"
cp "$PLUGIN_BIN/HelloPlugin" "$PLUGIN_BUILD/package/HelloPlugin"
cp Examples/HelloPlugin/plugin.json "$PLUGIN_BUILD/package/plugin.json"

In Linvell Dev, choose Edit → Load Development Plugin… and select ~/dev/build/linvell/hello-plugin/package. Review the trust notice and editor permissions, then choose Load Plugin. Open the command palette with ⌘⇧P and run Hello: Greet. The status bar shows the greeting.

Create a new text document, type a short line, then run Hello: Uppercase Document. The whole document is replaced and ⌘Z undoes the change. The command resets the selection to the beginning. It does not explicitly save the file; your existing auto-save policy still applies.

2. Describe the package

A package folder contains plugin.json and a compiled executable. Executable paths are relative to the package; absolute paths, parent traversal and symlinks escaping the package are rejected. No shell command or arguments are accepted. Build the executable for the Mac that runs it.

{
  "id": "dev.linvell.hello",
  "name": "Hello Swift",
  "version": "0.1.0",
  "protocolVersion": 1,
  "executable": "HelloPlugin",
  "permissions": ["document.read", "document.write"],
  "commands": [
    {"id": "hello.greet", "title": "Hello: Greet"},
    {"id": "hello.uppercase", "title": "Hello: Uppercase Document"}
  ]
}

protocolVersion must be 1. IDs use ASCII letters, digits, dots, underscores or hyphens (start with a letter or digit; at most 128 bytes). Command IDs must be unique within a package. Up to 100 commands and a 64 KiB manifest are accepted. name, version and command titles must be nonempty.

Only document.read and document.write are accepted in this preview. Write requires read. Use [] for message-only commands. Read permits the host to include the current document text and revision; write permits a returned replacement. The snapshot has no file path or workspace credentials.

Trust boundary: the executable runs as your user, outside a security sandbox. Manifest permissions gate editor APIs; they do not prevent direct file, network or process access. Load only trusted code. This preview has no plugin signing, marketplace or sandbox enforcement.

3. Write a Swift command

Depend on the LinvellPluginKit library product. The example uses a local path dependency on the repository. For your own package, set that path to your Linvell checkout, or pin a source revision that contains the SDK. Plugin code runs in its own executable, independently of the AppKit UI.

import LinvellPluginKit

try PluginServer.run { context in
    switch context.command {
    case "hello.greet": return PluginCommandResult(message:"Hello from a Swift plugin!")
    case "hello.uppercase":
        guard let document = context.document else { return PluginCommandResult(message:"Open a text document first.") }
        return PluginCommandResult(message:"Converted document to uppercase.",replacementText:document.text.uppercased())
    default: return PluginCommandResult(message:"Unknown command.")
    }
}

PluginServer.run performs framing and the handshake, then calls your handler for commands/execute. context.document is optional: no active document or no read permission means no snapshot. Return a message, a whole-document replacement, or both. Throw an error to report a command failure. Reserve stdout for the protocol; stderr diagnostics are discarded by the preview host, so use a development log file if needed.

4. Protocol 1 reference

Other languages can implement the same protocol. Use JSON-RPC 2.0 request/response objects over stdin/stdout, framed as Content-Length: N\r\n\r\n followed by exactly N UTF-8 bytes. N counts bytes, not characters. Echo the integer request ID. The Swift SDK accepts headers up to 8 KiB; JSON bodies are limited to 32 MiB by the SDK and host transport. Do not print banners or log lines to stdout.

// Host → plugin
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":1}}
// Plugin → host
{"jsonrpc":"2.0","id":1,"result":{"protocolVersion":1}}

// Host → plugin (document is omitted without permission or an active document)
{"jsonrpc":"2.0","id":2,"method":"commands/execute","params":{"command":"hello.uppercase","document":{"text":"hello","revision":7}}}
// Plugin → host
{"jsonrpc":"2.0","id":2,"result":{"message":"Done","replacementText":"HELLO"}}
// Command failure
{"jsonrpc":"2.0","id":2,"error":{"code":-32603,"message":"Unable to perform command"}}

Send one response per request. The host permits one command at a time per plugin per window. Each initialization and command request has a 10-second timeout. Current text and replacement text are each limited to 2 MiB of UTF-8, and a status message to 2,000 Swift characters. A result must be a JSON object; message and replacementText are optional strings.

The host applies replacement text only if the originating document, active pane, revision and original text still match, and no IME composition is active. Otherwise it rejects the result. Editing and undo use the native editor transaction. Remote buffers may be transformed locally, but the plugin process still runs on your Mac.

5. Lifecycle and troubleshooting

Loading reads the manifest without launching the executable. The process starts on the first command and is reused. Loading the same plugin ID again stops and replaces its previous session. Packages are loaded only in the current window; they are not persisted across app restarts. Project folders are never scanned for executable plugins.

Use Edit → Stop Plugins to stop all plugin sessions in the window. Closing the window also stops them. Stop interrupts pending work; unresponsive processes are force-terminated after a grace period. Crash, invalid replies or timeouts fail the session. Rebuild, copy the executable again and load the folder again to restart. The host does not automatically restart a failing plugin.

If loading fails, check that plugin.json is valid, protocolVersion is 1, the binary is executable and stays inside the package, and permission names are supported. If a command fails, check framing and stdout, architecture and runtime dependencies, and the timeout. If an edit is rejected after typing or navigation, run the command again on the new document version.

6. Available and planned

Available in source: explicit local development loading, process isolation, version handshake, command palette contributions, status messages, optional document snapshots and undoable whole-document replacements.

Planned: document events and range edits; menus, shortcuts and configuration/storage; declarative native trees, lists, panels and resource themes/snippets; language, task and debugger providers; remote plugin hosts. These APIs are not available yet. VSIX/Nova/Vim compatibility and a marketplace are outside the current scope.
