Build a Linvell plugin.

These APIs are implemented in unpublished source on main. Build from a checkout containing LinvellPluginKit; the current public app release does not include them. There is no separate dev branch.

Linvell Dev is the build script’s display name for the local debug app, used to distinguish it from the installed app. It is built from main, not a dev branch.

1. Build and load the example

Requirements: macOS 15.6 or newer, Xcode / a Swift 6 toolchain, and a source checkout of Linvell. The example is in Examples/HelloPlugin. Run the following from the repository root in Bash. Build output and caches stay under ~/dev/build.

bash script/build_and_run.sh --build-only
open "$HOME/dev/build/linvell/debug/Linvell.app"

PLUGIN_BUILD="$HOME/dev/build/linvell/hello-plugin"
mkdir -p "$PLUGIN_BUILD"/{package,tmp,cache,config,security}
export TMPDIR="$PLUGIN_BUILD/tmp"
export CLANG_MODULE_CACHE_PATH="$PLUGIN_BUILD/cache/clang"
export SWIFTPM_MODULECACHE_OVERRIDE="$PLUGIN_BUILD/cache/swift"
PLUGIN_ARGS=(--package-path Examples/HelloPlugin
  --scratch-path "$PLUGIN_BUILD/swiftpm"
  --cache-path "$PLUGIN_BUILD/cache"
  --config-path "$PLUGIN_BUILD/config"
  --security-path "$PLUGIN_BUILD/security")
swift build "${PLUGIN_ARGS[@]}" --product HelloPlugin
PLUGIN_BIN="$(swift build "${PLUGIN_ARGS[@]}" --show-bin-path)"
cp "$PLUGIN_BIN/HelloPlugin" "$PLUGIN_BUILD/package/HelloPlugin"
cp Examples/HelloPlugin/plugin.json "$PLUGIN_BUILD/package/plugin.json"

In Linvell Dev, choose Edit → Load Development Plugin… and select ~/dev/build/linvell/hello-plugin/package. Review the trust notice and editor permissions, then choose Load Plugin. Open the command palette with ⌘⇧P and run Hello: Greet. The status bar shows the configured greeting and a persistent invocation count.

Create a new text document, type a short line, then run Hello: Uppercase Document. The whole document is replaced and ⌘Z undoes the change. The command resets the selection to the beginning. It does not explicitly save the file; your existing auto-save policy still applies.

For P2, run Plugins → Hello Swift → Hello: Insert Prefix or ⌘⌃9. Use Hello: Document Events to inspect the last event. The same menu opens user and workspace configuration files.

2. Describe the package

A package contains plugin.json and an executable. Only package-relative executable paths are accepted; parent traversal and symlinks escaping the package are rejected. No shell command or arguments are accepted. Compile for the Mac’s architecture.

{
  "id": "dev.linvell.hello",
  "name": "Hello Swift",
  "version": "0.2.0",
  "protocolVersion": 1,
  "executable": "HelloPlugin",
  "permissions": [
    "document.read",
    "document.write",
    "storage"
  ],
  "commands": [
    {
      "id": "hello.greet",
      "title": "Hello: Greet",
      "menu": "plugins"
    },
    {
      "id": "hello.uppercase",
      "title": "Hello: Uppercase Document",
      "menu": "plugins"
    },
    {
      "id": "hello.prefix",
      "title": "Hello: Insert Prefix",
      "menu": "plugins",
      "keybinding": "cmd+ctrl+9"
    },
    {
      "id": "hello.events",
      "title": "Hello: Document Events",
      "menu": "plugins"
    }
  ],
  "events": [
    "open",
    "change",
    "save",
    "close"
  ],
  "configuration": {
    "greeting": "Hello from a Swift plugin!",
    "prefix": "Hello: "
  }
}

Protocol 1 remains compatible with P1 command-only packages. The P2 fields are optional. IDs use ASCII letters, digits, dots, underscores or hyphens, start with a letter or digit and contain at most 128 bytes. Command IDs must be unique within a package; up to 100 commands and a 64 KiB manifest are allowed.

document.read permits snapshots and is required for event subscriptions. document.write requires read and permits whole-document or range results. storage permits reading and patching this plugin’s global/workspace state. Configuration is always limited to the current plugin’s own settings.

Trust boundary: independent processes are not a security sandbox. Executables run with your OS user’s file, network and process access. Manifest permissions gate editor APIs only. Load trusted code; store no secrets in configuration or state.

3. Write Swift handlers

Depend on the LinvellPluginKit library product; see the example’s Package.swift. The SDK handles framing and initialization. Command and event handlers run serially in the same plugin process. Reserve stdout for protocol frames; the preview host discards stderr.

import LinvellPluginKit

try PluginServer.run(onEvent: { event in
    let count = event.environment?.globalState["eventCount"]?.number ?? 0
    return [
        PluginStateUpdate(scope:.global,key:"eventCount",value:.number(count+1)),
        PluginStateUpdate(scope:.global,key:"lastEvent",value:.string("\(event.kind.rawValue) @ revision \(event.revision)"))
    ]
}) { context in
    let environment = context.environment
    switch context.command {
    case "hello.greet":
        let greeting = environment?.configuration["greeting"]?.string ?? "Hello from a Swift plugin!"
        let runs = (environment?.globalState["runs"]?.number ?? 0)+1
        return PluginCommandResult(message:"\(greeting) (#\(Int(runs)))",stateUpdates:[PluginStateUpdate(scope:.global,key:"runs",value:.number(runs))])
    case "hello.uppercase":
        guard let document = context.document else { return PluginCommandResult(message:"Open a text document first.") }
        return PluginCommandResult(message:"Converted document to uppercase.",replacementText:document.text.uppercased())
    case "hello.prefix":
        guard let document = context.document else { return PluginCommandResult(message:"Open a text document first.") }
        let prefix = environment?.configuration["prefix"]?.string ?? "Hello: "
        return PluginCommandResult(message:"Inserted a prefix with a range edit.",edits:[PluginTextEdit(location:0,length:0,text:prefix)],documentRevision:document.revision)
    case "hello.events":
        let count = environment?.globalState["eventCount"]?.number ?? 0
        let last = environment?.globalState["lastEvent"]?.string ?? "none"
        return PluginCommandResult(message:"Document events: \(Int(count)); last: \(last)")
    default: return PluginCommandResult(message:"Unknown command.")
    }
}

context.document is optional. context.environment contains configuration, globalState and workspaceState. Values use the Codable PluginValue enum (string, number, bool, array, object, null). Old command handlers do not need to use the new fields.

4. Protocol 1 reference

Other languages can implement the same JSON-RPC 2.0 protocol over stdin/stdout: Content-Length: N\r\n\r\n, then exactly N UTF-8 bytes. N counts bytes. Echo the integer request ID; send exactly one response. The Swift SDK limits headers to 8 KiB; SDK and host limit JSON bodies to 32 MiB.

// Host → plugin
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":1}}
// P2 SDK → host (P1 command-only SDK may omit capabilities)
{"jsonrpc":"2.0","id":1,"result":{"protocolVersion":1,"capabilities":["documentEvents","rangeEdits","configuration","storage"]}}

{"jsonrpc":"2.0","id":2,"method":"commands/execute","params":{"command":"hello.prefix","document":{"id":"document-uuid","text":"hello","revision":7},"environment":{"configuration":{"prefix":"Hi: "},"globalState":{},"workspaceState":{}}}}
{"jsonrpc":"2.0","id":2,"result":{"edits":[{"location":0,"length":0,"text":"Hi: "}],"documentRevision":7,"message":"Done"}}

// Error response (fails this session; reload to restart)
{"jsonrpc":"2.0","id":2,"error":{"code":-32603,"message":"Unable to perform command"}}

Initialization, commands and event acknowledgements each have a 10-second request timeout. Work is serialized per plugin per window; a second command while one is pending is rejected. The current text and final replacement each have a 2 MiB UTF-8 limit; status messages have a 2,000 Swift-character limit. Unknown optional context fields can be ignored.

5. Document events

Declare events: ["open", "change", "save", "close"] and document.read. Loading replays open events for current text documents and can start the process immediately. Open, typing, editor transactions, undo/redo, acknowledged saves (including auto-save) and close feed the same event stream. Events never authorize automatic document editing.

{"jsonrpc":"2.0","id":3,"method":"documents/event","params":{"kind":"change","documentID":"document-uuid","revision":8,"document":{"id":"document-uuid","text":"Hi: hello","revision":8},"environment":{"configuration":{},"globalState":{},"workspaceState":{}}}}
{"jsonrpc":"2.0","id":3,"result":{"stateUpdates":[{"scope":"global","key":"lastRevision","value":8}]}}

Reply with an object containing optional stateUpdates; replacementText or edits in an event result are rejected. The SDK’s onEvent callback returns an array of state patches. Advertise documentEvents in the initialization result when implementing a custom runtime.

Pending changes for the same document are coalesced until a lifecycle boundary, so this is a snapshot stream, not a lossless keystroke log. Already queued events are handled before a command. At most 256 events may wait; overflow or handler failure stops the session. IME intermediate changes are deferred. Close, oversized documents and saves of an older revision carry metadata only (no document text). Closing a window stops the process without promising final close delivery.

6. Versioned range edits

Return edits with documentRevision matching the request. Each edit has zero-based location, length in UTF-16 code units and replacement text. A zero length inserts; empty text deletes. The host sorts edits and rejects overlaps, duplicate start positions, negative/out-of-bounds offsets and boundaries splitting Unicode characters. At most 1,000 edits and 2 MiB of inserted text are allowed.

Choose either edits or replacementText, never both. The originating document, pane, revision and text must still match, with no active IME composition. All ranges form one native undo transaction; range edits place cursors at edit ends. Existing auto-save policy still applies.

7. Menus and shortcuts

Set a command’s menu to "plugins" to contribute it to Plugins → Plugin Name. Commands remain in the command palette. Optionally set keybinding, such as "cmd+ctrl+9". Only this native menu target is supported in P2; editor context menus and arbitrary built-in menu insertion are not implemented.

Modifiers are cmd, ctrl, option, shift in any order, followed by one ASCII letter or digit. At least cmd or ctrl is required; no chords or function keys. Shortcuts require menu: "plugins". Conflicts with loaded plugins, existing app menu commands, common editing equivalents and the cmd-K chord prefix reject loading. Change the manifest and reload.

Contributions follow the key workspace window and disappear when stopped. Commands are disabled in other text-entry fields or while a sheet is attached, so plugin shortcuts do not override dialog text editing. macOS/global shortcuts and non-menu responder commands cannot all be detected automatically.

8. Configuration

The effective environment.configuration merges manifest configuration defaults, the plugin’s user configuration.json, then plugins[pluginID] in the current workspace’s .linvell/settings.json. This is a shallow merge by key: nested objects are replaced as a whole. Save edits before the next command/event to use them; unsaved settings are not applied.

// Workspace .linvell/settings.json (JSONC comments are supported)
{
  "plugins": {
    "dev.linvell.hello": {
      "greeting": "Hello from this workspace!",
      "prefix": "Project: "
    }
  }
}

Use Plugins → Hello Swift → User Plugin Configuration… or Workspace Plugin Configuration… to open the file in the native editor. The user file starts as {}; workspace initialization inserts only the plugin’s missing section and preserves comments and unrelated settings, with an external-change check. Local and SSH workspace settings use the existing settings transport; network/syntax errors are reported rather than silently replaced.

The user file lives under ~/Library/Application Support/Linvell/Plugins/<ID-digest>/configuration.json. Each override object is limited to 256 KiB; the shared workspace settings file retains its 1 MiB limit. Plugin commands cannot write configuration through the host API; configuration is explicitly edited and saved by the user.

9. Persistent state

With storage permission, command/event environments include this plugin’s globalState and workspaceState. Return stateUpdates patches instead of replacing snapshots. Use scope global or workspace, a nonempty key (at most 128 UTF-8 bytes), and a JSON value. Omit value to delete the key; explicit null stores null.

{"stateUpdates":[
  {"scope":"global","key":"runs","value":3},
  {"scope":"workspace","key":"lastAction","value":"prefix"},
  {"scope":"global","key":"obsolete"}
]}

State is stored locally in the plugin’s private namespace, including SSH workspace state. Workspace identity includes the canonical local project path, or SSH host alias plus root path. No-workspace contexts expose an empty workspace state and reject workspace updates. Different plugin IDs (including case differences) are isolated using a digest; no state is synced to iCloud or copied to the project.

At most 1,000 patches per response and 256 KiB per state file are accepted. File locking and read/merge/atomic-replace preserve unrelated keys from other windows; simultaneous updates to the same key are last-write-wins, not an atomic increment API. Corrupt/oversized files and symlinks are rejected without resetting state. Each file write is atomic, but global/workspace files and editor edits are separate operations. State may persist even if a later UI edit is rejected as stale. Stopping interrupts requests; a state write already committing may finish.

10. Lifecycle and troubleshooting

Command-only packages start lazily on their first command. Subscribed document events can also start the process after explicit loading. The same process is reused. Loading the same plugin ID again stops and replaces its previous session. Packages are loaded only in the current window; they are not persisted across app restarts. Project folders are never scanned for executable plugins.

Use Edit → Stop Plugins to stop all plugin sessions in the window. Closing the window also stops them. Stop interrupts pending work; unresponsive processes are force-terminated after a grace period. Crash, invalid replies or timeouts fail the session. Rebuild, copy the executable again and load the folder again to restart. The host does not automatically restart a failing plugin.

If loading fails, check that plugin.json is valid, protocolVersion is 1, the binary is executable and stays inside the package, and permission names are supported. If a command fails, check framing and stdout, architecture and runtime dependencies, and the timeout. If an edit is rejected after typing or navigation, run the command again on the new document version.

11. Available and planned

Available in source: explicit local loading, process isolation, version handshake, command palette and native Plugins menu, shortcuts with conflict detection, document events, undoable versioned range/whole-document edits, layered configuration and persistent plugin/global-workspace state.

Planned: declarative native trees, lists, panels and resource themes/snippets; language, task and debugger providers; remote plugin hosts. These APIs are not available yet. VSIX/Nova/Vim compatibility and a marketplace are outside the current scope.
