# Linvell 0.1.7 详细使用说明

## 自动保存与未保存标记

在“设置 → 编辑器”开启“自动保存改动”。停止输入约一秒后，已有路径的文件自动保存；支持本地和 SSH 文件，保留编码与换行。新建未命名文件仍需先“另存为”。

标签页中，未保存文件的关闭 X 显示为同尺寸圆点；成功保存后恢复 X。自动保存遇到外部改动会停止，并保留未保存状态，不覆盖外部版本。保存过程中继续输入的内容不会被误标为已保存。输入法正在组词时不会自动保存。

## 解释器与语言分析

先打开项目文件夹，再打开“设置 → 语言工具”。选择语言，检测或浏览该主机上的解释器／编译器、语言服务器，设置启动参数并应用。SSH 项目检测的是目标主机，而不是本机。

同一个项目可分别配置 Python、Swift、JavaScript、TypeScript、C、C++、Go、Rust、Java、C#、Ruby、PHP、Shell、Lua、R、Dart、HTML、CSS、JSON、Verilog、VHDL 等语言。解释器负责语言运行环境，语言服务器负责语义分析；如果未检测到服务器，需要先在所属主机安装对应工具，再选择其可执行文件。Linvell 不会自动从网络安装它们。

配置保存在项目根目录的 `.linvell/settings.json`，远程项目保存在远程项目根目录。每种语言单独存储，不互相覆盖；不通过 iCloud 同步主机路径。JSONC 注释、尾逗号和其他设置会被保留。示例：

```jsonc
{
  "[python]": {
    "linvell.interpreterPath": "${workspaceFolder}/.venv/bin/python",
    "linvell.languageServerPath": "${workspaceFolder}/.venv/bin/pylsp",
    "linvell.languageServerArguments": [],
    "linvell.languageServiceEnabled": true
  },
  "[swift]": {
    "linvell.interpreterPath": "/path/to/swift",
    "linvell.languageServerPath": "/path/to/sourcekit-lsp"
  },
  "files.associations": { "*.zig": "zig" },
  "[zig]": { "linvell.languageServerPath": "/path/to/zls" }
}
```

支持 `${workspaceFolder}`、`${userHome}` 和 `~/`；远程路径在目标主机展开。已有项目指定的可执行程序需要在语言工具页核对并应用后才运行。

## 跳转、提示与重构

| 操作 | macOS 快捷键／入口 |
| --- | --- |
| 跳转定义 | F12 或 ⌘单击 |
| 查找引用 | ⇧F12 |
| 返回／前进 | ⌃- / ⌃⇧- |
| 悬浮信息 | 鼠标停留，或 ⌘K 后按 ⌘I |
| 触发补全 | ⌃空格；输入时也会自动提示 |
| 重命名符号 | F2 或右键“重命名符号” |
| 保存全部 | ⌥⌘S |

重命名由语言服务器根据符号作用域生成修改，先显示文件及改动数量，确认后更新定义和引用，不做全项目字符串替换。跨文件修改可以一次撤销／重做；开启自动保存时随后写盘，否则保留圆点，等待保存。预览之后编辑器内容发生变化会拒绝应用旧计划。创建、移动、删除文件的重构不在本轮符号重命名范围内。

编辑器、补全列表、悬浮窗和重命名预览使用原生 Swift/AppKit；语言分析通过 Swift 实现的 LSP 客户端连接工具链。分析暂停于超过 2 MiB 的文件，重命名最多 500 个文件、32 MiB 原文，避免占用过多内存；文件编辑本身不依赖这些分析限制。跨文件准确性取决于所选语言服务器及其项目索引。

## Git 与 submodule

“源代码管理”提供改动、提交图谱、子模块和 Git 操作四个页面。

子模块页面显示路径、URL、分支、父仓库记录的提交、当前提交及修改／冲突状态。可添加、初始化、更新、递归同步 URL、设置跟踪分支、更改 URL、记录新引用、打开子仓库和移除。默认更新到父仓库记录的提交；“更新到分支最新提交”会获取新版本，之后需要在父仓库暂存引用并提交。安全移除会拒绝未提交改动、冲突或尚未被父仓库记录的提交，不强制丢弃内容。

“更多操作”进入原生参数表单，还可取消初始化、选择 merge／rebase 更新策略、查看递归状态／摘要、吸收 Git 目录，以及递归执行命令。取消初始化保留父仓库的子模块记录，移除则暂存删除，两者用途不同。

Git 操作页同时提供提交、分支、合并／变基及继续／中止、cherry-pick、revert、reset、文件恢复、冲突选边与标记解决、stash、标签、远程、reflog、worktree 等表单。写操作显示确切参数供核对，执行结果保留在原生输出区。高级参数采用 JSON 数组，直接传递给 Git，不经过 Shell 展开。

需要交互式 rebase、`git add -p`、编辑提交说明或其他任意 Git 命令时，使用“交互式 Git 控制台”。这是当前仓库所属主机上的真实 PTY；本地项目运行本地 Git，SSH 项目运行远程 Git。离开页面再返回会保留控制台和输出。关闭前先停止控制台或等待操作结束。少用命令不全部提供独立表单，可通过高级参数或控制台完成；本轮未实现图形化三方合并编辑器。

## 远程流畅性

远程目录列表缓存名称和路径，先显示缓存再后台读取；文件内容读取和冲突检测不使用陈旧目录缓存。“刷新”按钮强制获取目录变化。表格仅创建可见行，原生滚动与显示调度采用当前屏幕的刷新能力。

文件操作、Git、语言分析复用受权限保护的 SSH ControlMaster 连接；语言服务器在独立持久通道运行。轻量文件协议随本地客户端发送，使用主机已有 Python 3；无需从 GitHub 下载 Linvell server，也没有安装常驻 Linvell 服务。目标主机仍需安装所选语言工具。

布局耗时、事件循环响应和 display-link 回调频率是不同指标，不能据此保证所有画面始终达到屏幕最高帧率。网络等待在后台处理，缓存命中不等待 SSH。
